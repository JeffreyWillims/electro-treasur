# 🎯 Резюме на базе Citrine Vault — от проекта к офферу

Гайд, как превратить этот проект в **пушечное резюме** и начать выходить на интервью через hh.ru.
Внутри: готовый черновик резюме, формулы буллетов, ATS-ключевики, хаки под hh и пошаговый план.

> **Честно про «накрутку опыта».** Я помогу подать твой **реальный** опыт по максимуму — и этого хватит
> с запасом. Citrine Vault — это боевой продукт в проде (`citrinevault.ru`): async-бэкенд, JWT с
> ротацией refresh, Redis, фоновые воркеры, CI/CD, тесты, мониторинг. По уровню инженерии это Middle/Middle+.
> Чего делать **не надо**: выдумывать компании, которых не было, и приписывать лишние годы. Это вскрывается
> на техническом интервью за 10 минут и на проверке рекомендаций — и тогда сгорает всё. Вместо этого — ниже
> способы легально усилить формулировки: считать проект работой, мыслить достижениями с цифрами, говорить
> на языке вакансии. Так убедительнее, чем липовый стаж.

## 0. На какую роль целимся

Проект — фуллстек, но резюме всегда затачивается под **одну** роль. Выбери вектор (можно вести 2 версии резюме):

| Вектор | Заголовок в резюме | Что выпячиваем |
|---|---|---|
| **Backend Python** (рекомендую) | `Python Backend Developer` | FastAPI, async SQLAlchemy, Postgres, Redis, ARQ, JWT, Docker, тесты |
| **Fullstack** | `Fullstack Developer (Python / React)` | то же + React 19, TanStack Query, PWA |
| **Frontend** (если тянет туда) | `Frontend Developer (React / TypeScript)` | React 19, TS, Vite, PWA, Error Boundaries, дизайн-система |

Дальше примеры — под **Backend/Fullstack** (там проект сильнее всего).

## 2. Формула сильного буллета

Слабый буллет описывает **процесс**. Сильный — **результат с цифрой и технологией**.

```
[Действие-глагол] + [что именно/какой технологией] + [измеримый результат/зачем]
```

| ❌ Слабо | ✅ Сильно |
|---|---|
| «Работал с аутентификацией» | «Реализовал JWT-аутентификацию с ротацией refresh-токенов в Redis — сессии живут 7 дней, токен недоступен из JS даже при XSS» |
| «Писал тесты» | «Поднял покрытие до 488 тестов с изоляцией через SAVEPOINT — прогон всей интеграции за ~26 сек» |
| «Делал API» | «Спроектировал ~50 REST-эндпоинтов с OpenAPI-контрактом, из которого фронт генерирует TS-типы» |
| «Настроил деплой» | «Собрал CI/CD с zero-downtime миграциями и авто-деплоем на VPS — релиз в один git push» |

**Глаголы-стартеры:** спроектировал, реализовал, внедрил, оптимизировал, автоматизировал,
сократил, обеспечил, покрыл, настроил, вынес, устранил.

**Где взять цифры в этом проекте:** 488 тестов · покрытие ≥70% · ~50 эндпоинтов · 18 миграций ·
15-мин access / 7-дн refresh · 0 ₽ на LLM · время прогона тестов · размер бандла после ленивых чанков.

## 3. Хаки под hh.ru

hh — это поисковик + ATS. Резюме находят по ключевым словам, а рекрутер тратит на него ~7 секунд.

**Заголовок (важнейшее поле).** Пиши точное название роли, как в вакансиях: `Python-разработчик`,
`Backend-разработчик (Python)`, `Fullstack-разработчик`. Не «IT-специалист», не «программист-универсал».

**Ключевые навыки (теги).** hh ранжирует и фильтрует по ним. Забей теги ровно так, как их пишут в
вакансиях: `Python`, `FastAPI`, `PostgreSQL`, `Redis`, `Docker`, `SQLAlchemy`, `REST API`, `Git`,
`Linux`, `CI/CD`, `asyncio`, `Pydantic`, `Nginx`, `pytest`, `React`, `TypeScript`. 20–30 тегов — норм.

**Зарплатное ожидание.** Не оставляй пустым (пустое = отсеивают фильтром). Поставь чуть выше нижней
планки рынка по твоему грейду в городе — так попадёшь и в «дешёвые», и в «средние» фильтры.

**«О себе».** Первые 2 строки — самое цепляющее: роль + главный проект + стек. Их видно в выдаче.

**Сопроводительное (шаблон под отклик):**
```
Здравствуйте! Откликаюсь на «[название вакансии]».
Мой профильный опыт — Citrine Vault (citrinevault.ru): FastAPI + PostgreSQL + Redis,
JWT с ротацией токенов, фоновые воркеры ARQ, Docker и CI/CD. Совпадает с вашим стеком по
[Python/async/Postgres]. Готов показать код и рассказать про архитектурные решения на созвоне.
```

**Стратегия откликов.** 10–20 откликов в день, релевантных. Обновляй резюме перед волной откликов
(поднимает в выдаче — hh сортирует по дате обновления). Не бойся вакансий, где совпадение 70% — джуна/мидла
берут «на вырост».

**Ссылки — обязательно.** GitHub с этим репо + живое демо `citrinevault.ru` + Swagger `/docs`. Живой прод
в резюме джуна/мидла — редкость и мощный сигнал. Убедись, что репозиторий читаемый (README у тебя уже топовый).

## 4. Как позиционировать pet-project честно и сильно

- В блоке «Опыт» пиши проект как **работу**: роль, период, буллеты с результатами. Пометка
  «Собственный продукт / pet-project (production)» — это нормально и уважается.
- Не пиши «я junior» в тексте — пусть грейд определяет рекрутер по содержанию.
- Если коммерческого опыта нет — не ври про него. Скажи на созвоне: «Коммерческого пока нет, но вот
  боевой проект в проде, вот решения, вот тесты» — и веди разговор к коду. Это работает.
- «Учебный проект по гайду» и «спроектированный с нуля продукт в проде» — разные весовые категории.
  У тебя второе. Не приземляй себя словами.

## 5. Подготовка к интервью

Резюме открывает дверь — дальше решает разговор. Готовься по второму файлу:

➡️ **[INTERVIEW_QUESTIONS.md](INTERVIEW_QUESTIONS.md)** — 300 вопросов по проекту и стеку.

Как готовиться:
1. Иди по разделам, на каждый вопрос — сформулируй ответ **вслух**, своими словами.
2. Где плывёшь — открывай код проекта и разбирайся. Это и есть прокачка.
3. Особое внимание — «твои» темы из резюме: если написал «ротация refresh-токенов», ты обязан
   объяснить её на пальцах и на доске. Всё, что в резюме — потенциальный вопрос.
4. Подготовь **историю проекта** на 2 минуты: что, зачем, какие сложности, какие решения, что бы
   сделал иначе. Это спрашивают почти всегда.
