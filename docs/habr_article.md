Это история pet-проекта, который незаметно оброс PgBouncer'ом, мониторингом, CI с `mypy --strict` и выехал на боевой домен. По дороге я успел прикрутить ИИ-распознавание чеков, чуть не прикрутить LLM к финансовым советам — и вовремя остановиться. Спойлер из заголовка: самая «умная» фича проекта работает на чистых правилах, считается за микросекунды и стоит ноль рублей за инференс. А ещё расскажу, как папка с пробелом в имени чуть не уехала в прод и почему полный прогон mypy+pytest перед коммитом — это не паранойя.

## Что за продукт

**Citrine Vault** — персональный финансовый трекер: веб-приложение плюс Telegram-бот вокруг общего FastAPI-бэкенда. Живёт на [citrinevault.ru](https://citrinevault.ru), бот — [@citrine_vault_bot](https://t.me/citrine_vault_bot).

Веб — React 19 + Vite 8 (тот самый, на rolldown), Tailwind CSS с glassmorphic-интерфейсом, TanStack Query v5 для серверного стейта, Framer Motion для анимаций, Recharts для графиков. Бот — Aiogram 3. Из «ИИ» честно есть распознавание чеков и банковских выписок: фотографируешь чек, vision-модель разбирает сумму и категорию. А вот финансовые инсайты — принципиально без нейросетей, и об этом ниже.

Функционально это бюджетные конверты, дашборд доходов/расходов, Safe-to-Spend («сколько можно тратить в день до конца месяца»), импорт/экспорт CSV/XLSX и быстрый ввод трат через Telegram.

В релизе v1.1 приложение получило «кинетическую» мобильную адаптацию — нативные bottom sheets, жесты и плавные переходы на Framer Motion, чтобы веб в мобильном браузере ощущался как приложение, а не как сайт с гамбургер-меню. Туда же уехала асинхронная обратная связь: фидбек сохраняется и отправляется в фоне, интерфейс не блокируется ни на секунду. И главное изменение релиза, вынесенное в его девиз: приложение стало быстрее, безопаснее и умнее — без единого рубля на LLM-инференс.

## Архитектура: скучная, и это комплимент

Никакого Kubernetes-карго-культа в проде — Docker Compose на VPS (хотя k8s-манифесты в репозитории лежат, признаюсь, для души и HPA):

- **PostgreSQL 16** — основное хранилище. Деньги — `NUMERIC(12,2)`, и никак иначе.
- **PgBouncer** — connection pooling в transaction mode, pool 200. Asyncpg плодит соединения быстрее, чем Postgres успевает сказать «too many clients».
- **Redis 7** — кэш, rate-limiting, refresh-токены, идемпотентность и брокер очереди ARQ. AOF-персистентность, `allkeys-lru`, 256 МБ.
- **ARQ-воркер** — фоновые задачи: предрасчёт инсайтов, cron-рассылки. Тот же Docker-образ, что и бэкенд, просто другой entrypoint.
- **Nginx** — reverse proxy, SSL от Let's Encrypt, раздача статики. Отдельные конфиги для local и prod.
- **Мониторинг** — Prometheus + Grafana + Alertmanager + cAdvisor и экспортёры, отдельным compose-файлом.

CI на GitHub Actions: `ruff check` → `ruff format` → `mypy --strict` → `pip-audit` → `pytest` с порогом покрытия ≥ 70% → multi-stage Docker build → пуш в GHCR (только на push в `main`). `mypy --strict` на всём `src/` — это больно первые две недели и бесценно потом: Pydantic-модели типизируются через mypy-плагин, и целый класс ошибок «передал не ту схему» умирает на этапе CI. Для нагрузочных прогонов в репозитории лежит Locust-сценарий — полезно было убедиться, что PgBouncer в transaction mode действительно держит всплески, а не просто красиво стоит в docker-compose. Забегая вперёд: именно связка «полный mypy + полный pytest» однажды спасла прод.

API за это время разрослось до приличных размеров: `/v1` с auth, транзакциями, бюджетами, дашбордом, аналитикой, инсайтами и фидбеком, плюс публичное `/v2/public` по `X-API-Key`. Есть и позорный артефакт эволюции: годовой отчёт доступен по пути `/api/api/analytics/yearly` — двойной `/api` получился из-за наложения префикса роутера на nginx-прокси. Работает, задокументирован, оставлен как памятник «потом поправлю».

## Rule-Based Insight Engine: 130 строк вместо LLM

Хотелось фичу «умные финансовые советы»: открываешь приложение — а оно говорит, что бюджет на развлечения почти сгорел. Первый рефлекс в 2026 году очевиден: прикрутить LLM. Дальше арифметика.

Вариант «облачный API» — это деньги за каждый чих каждого пользователя и передача финансовых данных третьей стороне. Вариант «Ollama на своём VPS» ещё веселее: даже квантованная 7B-модель хочет несколько гигабайт RAM, а на VPS, где уже живут Postgres, Redis, два Python-процесса и nginx, свободной памяти примерно нисколько. Инференс на CPU — это секунды ожидания на простейший совет и стопроцентная утилизация ядер, которые нужны базе. И всё это ради текста уровня «вы много тратите на кофе».

Посмотрел на задачу трезво: какие советы реально полезны? «Бюджет категории почти исчерпан». «Сегодня подозрительно много трат». «Вот баланс месяца». Для всех трёх не нужна генерация — нужна арифметика. Так появился `RuleBasedInsightEngine` — 132 строки чистой бизнес-логики без единого I/O:

```python
class RuleBasedInsightEngine:
    """«Меню» правил аналитики; generate() возвращает одну строку по приоритету."""

    def generate(
        self,
        transactions: Sequence[TransactionData],
        budgets: Sequence[BudgetData],
    ) -> str:
        """Самое важное наблюдение за период: Budget Alert → Anomaly → Summary."""
        return (
            self._budget_alert(transactions, budgets)
            or self._anomaly(transactions)
            or self._cashflow_summary(transactions)
        )
```

Приоритет правил — просто цепочка `or`. Budget Alert срабатывает, когда категория съела ≥ 80% лимита (и из всех пробитых бюджетов выбирается худший по ratio). Anomaly ловит больше трёх расходных транзакций за день — маркер импульсивных покупок. Cashflow Summary — fallback, срабатывает всегда: доходы, расходы, сколько отложено.

Движок принимает не ORM-объекты, а frozen-датаклассы-«снимки»:

```python
@dataclass(frozen=True)
class TransactionData:
    """Снимок транзакции — только поля, нужные правилам."""

    amount: Decimal
    category_id: int
    category_type: CategoryType
    executed_at: datetime
```

Это дало неожиданно много: юнит-тесты без базы и моков (собрал список датаклассов — проверил строку на выходе), тривиальный `mypy --strict` и полную детерминированность. Ни одного «а почему модель сегодня ответила иначе».

Вторая половина решения — инсайты не считаются в момент запроса. ARQ-воркер предрассчитывает их в фоне и кладёт готовый текст в таблицу `insights` (upsert идемпотентен по паре user+period). Фронтенд читает готовую строку через `GET /api/v1/insights/latest` — 0 мс генерации при открытии плашки. А cron по воскресеньям в 18:00 UTC делает фан-аут по активным пользователям и с `notify=True` пушит недельный итог прямо в Telegram — советы приходят сами, без захода в приложение.

Итого: фича, ради которой просился LLM, работает на `Counter` и `defaultdict` из stdlib, отвечает мгновенно и масштабируется до любого числа пользователей ценой одного cron-джоба. LLM в проекте остался там, где без него правда никак: vision-распознавание чеков и годовой аналитический отчёт. Правильный вопрос — не «куда прикрутить нейросеть», а «где без неё нельзя».

## Zero-Friction: «Кофе 350» и починка раскладки

Главный убийца финансовых трекеров — трение при вводе. Если запись траты требует открыть приложение, нажать плюс и выбрать категорию из выпадашки — записи закончатся на третий день. Поэтому основной путь ввода — Telegram: пишешь боту `Кофе 350` (или `150 кофе` — порядок не важен), и через секунду транзакция в базе.

Парсер до неприличия прост: регулярка выдирает первое число как сумму, остаток строки — запрос категории. Дальше словарь синонимов маппит бытовые слова на системные конверты:

```python
CATEGORY_SYNONYMS = {
    "такси": "Operations (Rent/Utility)",
    "продукты": "Operations (Rent/Utility)",
    "кофе": "Leisure (Lifestyle)",
    "ресторан": "Leisure (Lifestyle)",
    "аптека": "Wellness (Health)",
    "зарплата": "Propulsion (Income)",
    "акции": "Growth (Investments)",
}
```

Если категория не написана — бот присылает inline-клавиатуру с конвертами. Если написана, но не распознана — идёт поиск по названиям категорий пользователя.

Моя любимая мелочь. В логах регулярно всплывали сообщения вида `ghjlerns 500` — люди печатают, не глядя на раскладку. Вместо ответа «не понял» — транслитерация QWERTY → ЙЦУКЕН одной таблицей:

```python
def _fix_layout(text: str) -> str:
    """Переводит английскую раскладку в русскую ('ghjlerns' -> 'продукты')."""
    en = "qwertyuiop[]asdfghjkl;'zxcvbnm,./"
    ru = "йцукенгшщзхъфывапролджэячсмитьбю."
    tr = str.maketrans(en, ru)
    return text.translate(tr)
```

Шесть строк, `str.maketrans` из коробки — и целый класс «непонятных» сообщений превращается в валидные транзакции.

Теперь про надёжность. Telegram умеет доставлять апдейты повторно, пользователи умеют дважды тыкать в inline-кнопку. Без защиты это двойные списания. Решение двухслойное: детерминированный ключ идемпотентности из атрибутов сообщения плюс UNIQUE-констрейнт в Postgres:

```python
raw_key = f"tg_{message.chat.id}_{message.message_id}_{category.id}_{amount}"
idempotency_key = str(uuid.uuid5(uuid.NAMESPACE_URL, raw_key))

dup_check = await session.execute(
    select(Transaction).where(Transaction.idempotency_key == idempotency_key)
)
if dup_check.scalar_one_or_none() is not None:
    return
```

`uuid5` — это SHA-1 от неймспейса и строки: один и тот же апдейт всегда даёт один и тот же UUID. Проверка перед вставкой отсекает повторы вежливо, а UNIQUE-индекс страхует от гонки двух конкурентных обработчиков — БД как последняя линия обороны. Тот же заголовок `Idempotency-Key` работает и в REST API для батч-импорта.

## Инженерная гигиена: три решения, которыми доволен

**API-ключи: Argon2 + открытый prefix.** Для публичного `/v2/public` нужны были API-ключи. Хранить плейнтекстом нельзя, хранить только Argon2-хэш — нельзя искать: Argon2 намеренно медленный, и перебор всех хэшей на каждый запрос — это DoS своими руками. Формат `cv_{prefix:8 hex}{secret:32 hex}` решает обе проблемы: prefix лежит открыто с UNIQUE-индексом, поиск за O(1), а верифицируется полный ключ одной Argon2-проверкой:

```python
def generate_plain_key() -> tuple[str, str]:
    """Возвращает (полный ключ, prefix). Секрет — 16 байт CSPRNG."""
    prefix = secrets.token_hex(PREFIX_HEX_LEN // 2)
    secret = secrets.token_hex(SECRET_HEX_LEN // 2)
    return f"{KEY_NAMESPACE}{prefix}{secret}", prefix
```

Полный ключ показывается пользователю ровно один раз при создании — дальше только хэш. Та же схема, что у GitHub с их `ghp_`-токенами, и она хороша.

**Savepoint-изоляция тестов.** Классика асинхронных интеграционных тестов — либо пересоздавать базу на каждый тест (медленно), либо ловить утечки состояния между тестами (больно). У нас каждый тест живёт внутри собственного `SAVEPOINT`: фикстура делает `session.begin_nested()`, код приложения спокойно зовёт `commit()` — коммитится только savepoint, — а после теста происходит откат, и база снова чистая. Сотни интеграционных тестов на реальном Postgres без единого `TRUNCATE`.

**Refresh-токены в Redis с ротацией.** После перехода на Secure HttpOnly Cookies access-токен живёт 15 минут, refresh — в Redis с TTL. При каждом рефреше старый токен отзывается немедленно и выдаётся новая пара: украденный refresh-токен можно использовать один раз, и повторное использование — сигнал компрометации. Токены недоступны из JavaScript, так что даже XSS не уносит сессию.

## Что пошло не так: папка с пробелом внутри пакета

Обещанная честная глава. 5 июля — инцидент INC-2026-07-05-01, звучит смешно, было не очень.

В репозитории есть каталог `backend/src/agents/` — Python-каркас агентной подсистемы. При наведении порядка drag-and-drop'ом в IDE он уехал в `backend/src/ .claude/agents/`. Да, с **ведущим пробелом в имени каталога**. Внутри пакета `src/`.

Последствия по нарастающей: `src.agents` перестал импортироваться — пробел в пути не может быть частью имени Python-модуля, и `tests/unit/test_agents.py` упал с `ModuleNotFoundError`. Затем `mypy --strict src/` просканировал файлы по новому пути и покраснел (`orchestrator.py: no-any-return`). А главное — перенос успел попасть в локальный коммит `6c62f09`.

Поймал это рутинный QA-прогон перед сборкой фронтенда: полный `pytest tests/unit` плюс полный `mypy src/`. Не «проверю только свои файлы», а именно полный прогон — точечная проверка этот класс проблем не ловит в принципе, потому что сломались не «мои» файлы, а структура пакета. `git log -- 'backend/src/ .claude'` показал виновника, `mv 'backend/src/ .claude/agents' backend/src/agents` вернул всё на место. Контрольная проверка после отката: ruff чистый, mypy — 0 ошибок в 73 файлах, 263 юнит-теста зелёные, Docker-сборка проходит. В origin поломка не уходила, амендить историю не стали — фикс уехал следующим коммитом.

Уроки записаны в `docs/INCIDENTS.md` (да, у pet-проекта есть журнал инцидентов, и это лучшее, что я завёл): конфигурация инструментов вроде `.claude/` живёт в корне репозитория, а не внутри Python-пакета; полный mypy+pytest перед каждым коммитом обязателен; каталоги с пробелами внутри пакетов недопустимы в принципе. Скучные правила, но именно скучные правила ловят весёлые баги.

## Что дальше

Из ближайшего: CI уже собирает и пушит образы в GHCR, но деплой пока руками — следующий шаг честный CD. Из стратегического — монетизация: публичное API по ключам уже есть, дальше — платные тарифы поверх него.

Главный вывод трёх месяцев эксплуатации: pet-проект становится продуктом не в момент покупки домена, а в момент, когда у тебя появляются журнал инцидентов, порог покрытия в CI и привычка спрашивать «а нужна ли здесь нейросеть?» до того, как её прикрутил.
