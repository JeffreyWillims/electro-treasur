## INC-2026-07-05-01 — Сломанный перенос `src/agents` → `src/ .claude/`

**Дата:** 5 июля 2026 · **Серьёзность:** средняя (сборка/CI) · **Статус:** ✅ устранён

### Что случилось
Каталог мультиагентной подсистемы `backend/src/agents/` был перемещён (drag-and-drop в IDE)
в `backend/src/ .claude/agents/` — в директорию с **ведущим пробелом в имени**, внутри
пакета `src/`.

### Последствия
- `src.agents` перестал импортироваться (пробел в пути — невалидное имя Python-модуля):
  `tests/unit/test_agents.py` падал с `ModuleNotFoundError`.
- `mypy --strict src/` сканировал перенесённые файлы по новому пути и давал ошибку
  (`orchestrator.py: no-any-return`) — CI-шаг `mypy src/` стал красным.
- Перенос успел попасть в локальный коммит `6c62f09` (в origin **не** уходил).

### Как обнаружили
QA-прогон перед сборкой фронтенда: `pytest tests/unit` (ModuleNotFoundError) +
полный `mypy src/` (1 ошибка в `src/ .claude/…`). Git-история (`git log -- 'backend/src/ .claude'`)
показала, что перенос попал в последний локальный коммит.

### Устранение
Каталог возвращён на место: `mv 'backend/src/ .claude/agents' backend/src/agents`,
пустая `' .claude'` удалена. Проверка после отката: ruff ✅ · mypy 0 ошибок (73 файла) ✅ ·
263 unit-теста ✅ · Docker-сборка фронтенда ✅. Исправление вошло в следующий коммит
(амендить историю не стали).

### Уроки / профилактика
1. **Намерение**: если цель была создать subagents для Claude Code — их определения
   живут в **корне репозитория** `.claude/agents/*.md` (markdown с frontmatter),
   а не внутри `backend/src/`. Python-каркас `src/agents/` трогать для этого не нужно.
2. Полный прогон `mypy src/` + `pytest` обязателен перед каждым коммитом — точечная
   проверка «только своих файлов» этот класс проблем не ловит.
3. Каталоги с пробелами в имени внутри Python-пакетов недопустимы в принципе.
