# tests/integration/

Интеграционные тесты: реальный PostgreSQL, полный путь запроса —
HTTP через `httpx.AsyncClient` → роут FastAPI → сервис → ORM (SQLAlchemy) → БД.
Изоляция между тестами через SAVEPOINT / nested transaction (см. `tests/conftest.py`
в корне `tests/`). `integration/conftest.py` автоматически скипает все тесты этой
папки, если PostgreSQL недоступен (`pytest_collection_modifyitems` + проверка
`SELECT 1` на тестовой БД).

## Файлы

- `__init__.py` — пустой маркер пакета с комментарием о характере папки (реальный PostgreSQL, откат транзакций).
- `conftest.py` — guard: проверяет доступность тестового PostgreSQL и, если он недоступен, помечает все тесты `integration/` как skip вместо падения с `ConnectionRefusedError`.
- `test_api.py` — `POST /v1/transactions/`: успешное создание (201, тело ответа, запись реально попадает в БД), создание со случайными данными фабрики, и невалидные payload'ы (нечисловая сумма, отсутствие `category_id`, запрос без авторизации → 422/401).
- `test_api_full.py` — полный CRUD по основным эндпоинтам: `GET /v1/health`; `POST/GET/PATCH/DELETE /v1/transactions/` (список, пагинация, фильтр по сумме, обновление, удаление, повторное удаление); `PUT/DELETE /v1/budgets/` (upsert, обновление существующего, удаление, 404); `GET/PATCH /v1/users/me`; `POST/GET/PATCH/DELETE /v1/users/categories` (+ `transaction-count`); `POST /v1/auth/register` и `POST /v1/auth/login` (успех, дубликат email, неверный пароль, несуществующий пользователь, cookie-токены); `GET /v1/transactions/export` (CSV).
- `test_cashflow_prep.py` — сервис `cashflow_prep` и воркеры инсайтов: `get_active_user_ids` (фильтр по периоду), `upsert_insight` (идемпотентность), `calculate_static_insights` (детерминированный текст «Итог месяца…»/«Совет:»), `generate_period_insight` (реальные суммы дохода/расхода/normы сбережений), `schedule_monthly_analysis` (fan-out задач на всех активных пользователей), `get_linked_users_without_tx_on` (пользователи без транзакций сегодня), `get_free_funds` (арифметика доход-расход и остатки по конвертам бюджета).
- `test_dashboard.py` — `GET /v1/dashboard/`: агрегация матрицы по дням (суммирование транзакций одного дня в одну ячейку), план/факт/дельта по категориям, общий баланс за всё время, отклонение диапазона дат (start > end → 400, диапазон больше 90 дней → 400).
- `test_feedback.py` — `POST /v1/feedback/` (200 при авторизации, 401 без неё, 422 на пустое сообщение), персистентность `save_feedback` в БД и коммит транзакции; чтение окна «Обратная связь»: `GET /v1/feedback/` закрыт (403) для обычных пользователей и при пустом `ET_FEEDBACK_ADMIN_EMAILS`, владелец видит список с email автора и счётчиком непрочитанных, `PATCH /v1/feedback/{id}/read` и `PATCH /v1/feedback/read-all` гасят счётчик.
- `test_games.py` — `POST /v1/games/score` (сохранение рекорда, апдейт только при улучшении результата — upsert best-only), `GET /v1/games/leaderboard` (сортировка по убыванию), авторизация обязательна, неизвестная игра → 422.
- `test_goals.py` — Savings Goals API (`POST/GET/PATCH/DELETE /v1/goals/...`): создание цели с прогрессом, список целей с изоляцией по пользователю, взнос (`contribute`) с ограничением прогресса 100%/остатка 0, создание и переиспользование категории «Цель: {имя}» с расходной транзакцией типа `goal_contribution`, взнос в несуществующую цель → 404, удаление цели.
- `test_health_score.py` — `GET /v1/health-score/`: требует авторизацию (401), возвращает индекс 0-100 с тремя факторами (норма сбережений/цели/бюджеты) на заполненных данных, и нейтральный балл (30) при отсутствии данных у пользователя.
- `test_import_export.py` — `import_transactions`: создание транзакций из CSV, автосоздание отсутствующей категории, идемпотентность (повторный импорт не дублирует), пустой CSV/отсутствующая обязательная колонка/неподдерживаемый формат → ошибки, распознавание русских названий колонок (Дата/Сумма), пропуск строк с нулевой суммой; `export_transactions_csv`: пустой пользователь (только заголовок), CSV с данными транзакции, возврат `BytesIO` с UTF-8 BOM.
- `test_imports.py` — `POST /v1/imports/statement` (постановка задачи парсинга в очередь arq, отклонение неподдерживаемого расширения файла), `GET /v1/imports/{task_id}` (неизвестная задача → 404), `POST /v1/imports/confirm` (создание транзакций из подтверждённых кандидатов и идемпотентный повтор без дублей).
- `test_jobs.py` — SSE-стрим `GET /v1/jobs/{task_id}/stream`: требует авторизацию (401), успешное завершение с результатом владельца задачи, ошибка при попытке подключиться к чужой задаче.
- `test_jwt_refresh.py` — cookie-based аутентификация и ротация refresh-токена: логин выставляет httpOnly cookies без токенов в теле, просроченный access-cookie → 401, запрос без cookie → 401, обмен refresh-токена выдаёт новую пару и мгновенно инвалидирует старый (rotation), refresh без cookie/с мусорным токеном → 401, logout очищает cookies и отзывает refresh в Redis.
- `test_notifications.py` — `GET /v1/notifications/` (ленивый идемпотентный посев записей «Что нового»), `POST /v1/notifications/read-all` (сброс счётчика непрочитанных), создание уведомления о новом игровом рекорде без дублей, `GET /v1/games/leaderboard/total` (сумма очков по всем играм), требование авторизации на всех эндпоинтах.
- `test_offers.py` — `GET /v1/offers/` (только активные предложения, сортировка по `sort_order`), `POST /v1/offers/{id}/click` (инкремент счётчика кликов, 404 для неизвестного предложения), `GET /v1/insights/latest` (null при отсутствии инсайтов, последний по периоду при наличии).
- `test_psychopassport_worker.py` — `calculate_static_insights` кладёт в `summary` валидный «психопаспорт» (persona_code, persona_title, traits, recommendations) на основе структуры расходов, не ломая существующие поля summary.
- `test_public_api.py` — `/v2/public`: неверный API-ключ → 401; рейт-лимитер (60 запросов в минуту проходят, 61-й `GET /v2/public/categories` → 429).
- `test_report.py` — `GET /v1/reports/financial-plan.pdf`: валидный PDF без данных пользователя, PDF с инсайтом и целью (нетривиальный размер документа), требование авторизации (401).
- `test_repositories.py` — ORM-ограничения на уровне PostgreSQL: UNIQUE `idempotency_key` у транзакций (и разрешённость нескольких NULL), UNIQUE `email` и `telegram_chat_id` у пользователей, UNIQUE `(user_id, category_id, month, year)` у бюджетов (и допустимость разных месяцев), CASCADE-удаление транзакций при удалении пользователя/категории, точность `NUMERIC(12,2)` для сумм транзакций и `monthly_income`.
- `test_security_p0.py` — регрессия P0 (Broken Access Control) на poll-эндпоинтах: `GET /v1/insights/{task_id}` и `GET /analytics/tasks/{task_id}` без JWT → 401, чужая задача → 404 (проверка владения по `args[0]`), своя незавершённая задача → 200 `{"status": "pending"}`.
- `test_tax.py` — `GET /v1/tax/search` (полнотекстовый поиск Postgres FTS: релевантный результат первым, пустой запрос возвращает всё, OR-семантика по частичным терминам, отсутствие совпадений → пустой список), `GET /v1/tax/categories`, `GET /v1/tax/deductions` (виды вычетов), `POST /v1/tax/calc` (расчёт суммы возврата, неизвестный вид вычета → 400), требование авторизации.
- `test_user_service.py` — `create_user` (хэширование пароля, посев 6 стандартных категорий, нулевой `monthly_income` по умолчанию), `get_user_by_email`, `update_user_profile` (имя/доход/телефон), CRUD категорий (`create_user_category`, `update_user_category` с проверкой владения, `count_category_transactions` с sentinel-значением `-1` для чужой категории, `delete_user_category` с каскадным удалением транзакций и бюджетов, удаление несуществующей категории → `False`).
- `test_yearly.py` — регрессионный тест: `POST /analytics/yearly` ставит в очередь `generate_period_insight` с корректным диапазоном дат за весь год (`user_id`, `2026-01-01`, `2026-12-31`), а не сырым `year` из тела запроса.
